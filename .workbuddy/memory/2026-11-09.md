## 修复：切换主题按钮"没反应"

- 两处原因：
  1. `cycleTheme` 是三态循环 system → light → dark → system。OS 为浅色时
     第一次点击 system→light 视觉毫无变化（只有图标 ◑→☀），用户以为按钮坏了。
  2. `initThemeListener()` 先调 `mq.addEventListener(...)` 再注册
     `themeMode.subscribe(...)`；若 WebView 的 MediaQueryList 不支持/抛错，
     订阅永远没注册，之后点按钮只改 store 和图标，`html.dark` 始终不变。
- 修复（`src/lib/stores/theme.ts`）：删除 `cycleTheme`，新增 `toggleTheme()`，
  按 `getEffectiveTheme()` 明暗取反并**立即** `applyCurrentTheme()`；
  `initThemeListener` 把 store 订阅前置，媒体查询监听加 try/catch +
  `addListener` 兜底；`getSystemTheme` 也吞掉 matchMedia 异常。
  调用点：`Toolbar.svelte` 按钮、`+page.svelte` 的 `__mdhero_toggle_theme`
  （原生菜单）统一改用 `toggleTheme()`。
- 新增 `tests/unit/theme.test.ts`（4 用例：浅色/深色 OS 首次点击可见、
  matchMedia 抛错仍生效、无 document 时安全）。
- 验证：`vitest run` 44 文件 / 481 用例全绿；`svelte-check` 0 errors
  （8 条既有警告未变）。
- 行为变化：按钮从三态循环改为明暗两态切换；"跟随系统"在重启后恢复
  （themeMode 不持久化，初值 system）。

## 修复：新建文档保存按钮失效、无法保存

- 三处叠加原因：
  1. `new://` 文档初始 `dirty=false`；Toolbar 保存按钮 `disabled={!dirty}`，
     `handleSave` 又第一行 `if (!tab.dirty) return true`，第一次保存（Save As
     选路径）永远不会触发，形成死循环。
  2. 双栏模式下编辑器绑定 `leftTab`，但 `dirty` / `onSave` / Cmd+S 绑定
     `activeTab`（跟随 focusedPane）；焦点在右栏时左栏编辑的 dirty 到不了按钮。
  3. `newDocument()` 用默认 `pane = focusedPane`，焦点在右栏时新标签落到
     只读右栏（编辑器只在左栏），既不能输入也不能保存。
- 改动：新增 `src/lib/utils/tab-save.ts`（`needsSaveAs` / `canSaveTab` 纯函数）；
  `Toolbar.svelte` 加 `canSave` prop，`disabled={!canSave}`；
  `+page.svelte` 新增 `editorTab`（左栏在编辑时取 leftTab，否则 activeTab），
  dirty/canSave/onSave/Cmd+S 统一用它，`handleSave` 对 new:// 不再提前 return；
  `src/lib/tauri/files.ts` 的 `newDocument()` 固定 `pane: "left"`。
- 新增 `tests/unit/tab-save.test.ts`（4 用例）。
- 验证：`vitest run` 45 文件 / 485 用例全绿；`svelte-check` 0 errors。
- 行为变化：新建文档即使一个字都没写，也能点保存（弹出另存为写空文件）；
  保存按钮与 Cmd+S 始终针对编辑器里正在编辑的文档。

## 修复：新建文档后标签不能跨栏拖动、查看模式点不动

- 根因在 `setMode("view")`：它先调 `tabStore.collapseRightPane()`，于是
  (a) 双栏被关、右栏消失，标签自然没有"左右"两栏可拖；
  (b) collapse 会把 `activeIds.left` 换成右栏文档，`currentMode` 随之变
  `viewer`，`switchMode` 的 `target === currentMode` 直接 return；同时
  `switchMode` 用的是 `activeTab`（焦点栏、只读右栏），退不出左栏的编辑状态。
- 修复（`src/routes/+page.svelte`）：
  * View 只切左栏显示模式，不再 collapse；Dual 段改成 toggle，
    点已高亮的 Dual 才 `collapseRightPane()`（保留关闭双栏的入口）。
  * `switchMode` / `setMode` / `handleEditToggle` / `handleRawToggle` /
    `togglePresent` 与 `canEditActive`、Toolbar 的 `isEditing` prop 统一改用
    `editorTab`（左栏在编辑时取 leftTab，否则 activeTab）。
- 验证：`vitest run` 45 文件 / 485 用例全绿；`svelte-check` 0 errors。
- 构建：本环境 safe-delete 拒绝删除 `build/`，adapter-static 无法清空目录，

## 修复：新建文档保存后 UI 卡死、标签不更新文件名

- 两个根因：

  2. 系统另存为对话框不保证补扩展名；用户输入不带 `.md` 的名字时，
     `write_markdown_file` 的文本扩展名白名单（commands.rs，
     md/markdown/mdown/mkd/mdx/txt/text）拒绝写入，`saveFile` 抛错，
     `rebindPath` 没执行 → 标签保持"未命名"。

  * `+page.svelte`：保存失败与"已是最新版本"两处 `alert()` 改成 `showToast()`
    （非阻塞，保存失败会显示 Rust 返回的具体原因）。
  * `utils/path.ts` 新增 `withDocumentExtension()`：无扩展名或扩展名不在后端
    白名单时补 `.md`；`files.ts` 的 `saveAsNewDocument()` 先规范化路径再写盘、
    再 rebind。
  * `tests/unit/path.test.ts` 增 3 组用例覆盖扩展名规范化。
- 验证：`vitest run` 45 文件 / 488 用例全绿；`svelte-check` 0 errors。

## 根因确认：保存后页面冻结 = WebView2 遮挡挂起

- 用户重启后仍是：保存成功（窗口标题变 `可以啊.md`，Rust 侧正常），但标签仍
  "未命名"、点标签/关闭/查看全无反应。localStorage 里没有新文件名，说明渲染进程
  的后续 JS（markSaved/docStore.set/persistSession）都没跑完。
- 取证（Python + Win32）：
  * 主窗口 `IsWindowEnabled=True`、无阻塞 popup → 不是系统模态；
  * 所有 WebView2 进程 3 秒 CPU 增量 ≈ 0 → 不是死循环；
  * `PrintWindow` 能拿到最后一帧；`SetCursorPos` 悬停标签前后像素差 = 0 →
    **页面完全不重绘、不响应鼠标**；
  * 刷新页面（新的 renderer 进程）后恢复正常 → 渲染进程被挂起/冻结。
- 根因：Tauri 在 Windows 上默认 `background_throttling = Suspend`（该配置项在
  Windows 不生效，只能靠 Chromium 参数）。原生保存对话框盖住主窗口后，Chromium
  用 `CalculateNativeWinOcclusion` 判定窗口被遮挡并挂起 renderer，对话框关闭后
  没有再重新计算可见性，于是永久冻结：最后一帧保留、Rust 标题能改、页面全死。
- 修复：`src-tauri/tauri.conf.json` 的窗口配置新增 `additionalBrowserArgs`：
  `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection,CalculateNativeWinOcclusion
   --disable-backgrounding-occluded-windows --disable-renderer-backgrounding
   --disable-background-timer-throttling`
  （保留 Tauri 默认的 disable-features 三项，否则会覆盖丢功能）
- 生效条件：**必须完全重启 `pnpm tauri dev`**——浏览器参数只在 WebView2 启动时
  传入，刷新页面无效。
- 同时移除了 `+layout.svelte` 里的临时 console.error→title 诊断。
- 验证：`vitest` 45 文件/488 用例全绿，`svelte-check` 0 errors，`tauri info`
  配置解析正常。

## 真根因：新建文档后 UI 冻结 = derived 里写 store（state_unsafe_mutation）

- 遮挡挂起不是根因（浏览器参数已生效仍复现）。用 CDP（`--remote-debugging-port=9222`）
  连进页面取证：主线程正常、DOM 里标签确实是"未命名"、store 里已是"测试.md"，
  但 `tabs.set` 不再通知任何订阅者，新建 store 也收不到通知 →
  Svelte store 的全局 `subscriber_queue` 残留卡死。
- `Debugger.setPauseOnExceptions` 抓到真实异常链：
  `showToast → toasts.update → writable.set`
  ← `createParasSession` ← `getParasSession` ← `activeParasSession`($derived)。
  即新建 `new://` 文档时，`createParasSession` 在 derived 计算中弹"内存模式"
  toast（写 store），Svelte 5 抛 `state_unsafe_mutation`；该异常打断了
  store 的订阅派发循环，`subscriber_queue` 留下残留条目，此后所有 store
  更新只入队不派发 → 标签不更新、点击全部无效。
- 修复：`src/lib/paras/store.ts` 的"内存模式"toast 改为
  `setTimeout(() => showToast(...), 0)`，脱离 derived 计算。
- 防御性补丁：`node_modules/svelte/src/store/shared/index.js` 与
  `node_modules/.vite/deps/chunk-CURZ7JWI.js` 的 flush 循环包 try/finally，
  保证 `subscriber_queue.length = 0`（pnpm install 会丢失，属临时保护）。
- 验证：重新加载页面后用 CDP 模拟 addTab → rebindPath → markSaved → closeTab，
  DOM 依次显示 未命名 → verify.md → 移除，全部实时更新 ✓。
- 移除 tauri.conf.json 里的 `--remote-debugging-port=9222`，保留遮挡挂起相关
  的防御参数。

## 02:35 翻译报错排查（LM Studio 网络开关）
- 现象：`Request to http://192.168.1.13:1234/v1/chat/completions failed: error sending
  request for url`（Rust reqwest 的 connect 层错误，非 HTTP 状态码）。
- 根因：LM Studio 未开启「网络中的服务」，服务只监听 127.0.0.1:1234；`192.168.1.13:1234`
  连接被拒绝（os error 10061）。用户打开开关后已恢复。
- 验证：`/v1/models` 返回 200（模型 hy-mt2-1.8b / 7b）；非流与流式（SSE）翻译请求均正常。
- 顺带发现：本机系统代理开启（Mihomo/Clash 127.0.0.1:7900），代理 bypass 已含
  `192.168.*`，且 reqwest 走自身环境代理时局域网直连不受影响；curl 走代理会 502，
  加 `--noproxy '*'` 即可。以后排查同类连接问题先分清是代理层还是服务未监听。
- 经验：LM Studio 服务地址建议优先用 `http://127.0.0.1:1234`（不依赖网络开关，
  换网络/IP 变化也不会失效）。
